# The compositor

`edel-compositor`: windows, floating and tiling, title bars, outputs and effects (ADR-002), one of the two long-running processes of the Edel shell. Edition 2024, `rust-version = "1.85"`, GPL-3.0-or-later, `publish = false`. Built on smithay, pinned to `=0.7.0` with only the features in use.

## What belongs here

- Window management, outputs, input routing, title bars, effects and the frame loop. The panel, dock, launcher and notifications belong to shell-ui (M5); settings pages to Settings.
- No extension API, no theme engine, no second renderer (GLES only), no IPC daemon (ADR-002). Floating and tiling are two implementations of `layout::WindowPolicy`, chosen per workspace.
- Colours and sizes come only from `design/tokens.toml` through `tokens::Tokens`; never hard-code one in drawing code.
- **A game plays alone (M7.7c):** on a screen where `playing_on` names a window (game mode, a fullscreen top window, no lock, no overview), `Edel::elements` draws that window, the overlays and the cursor only, and the backends give frame callbacks to it and the overlays only (`behind_game`, `layers::send_frames`' `only`). New drawing or a new kind of surface keeps to that: check `playing_on` before drawing anything behind the game. The battery is shell-ui's to read (`on_battery`, `battery_changed`); the compositor reads it once, at start.
- Readers of files other releases write (tokens, later `settings.toml`) are lenient: unknown keys and bad values keep the built-in value and are reported, never fatal (ADR-008). `tokens::check` is the strict reader for tests and builds.
- **Stands alone (M8.13):** it needs the `edel` library without its `cli` and `os` features (M6.17: the settings format and its models only), runs by name only the programs `ci/seams.sh`'s `allowed_program()` lists (`edel-shell-ui`, `xwayland-satellite`, `fcitx5`, M6.17), a Wayland and DRM stack (libinput, libseat, GBM, EGL, libxkbcommon) and the files `edel::places` names. It never depends on shell-ui, Settings or the test client, and speaks to shell-ui only through Wayland protocols, `edel-shell-v1` among them (`ci/seams.sh`).

## Running it

On a desktop with X11 or Wayland: `cargo run -p edel-compositor --features winit`, then `WAYLAND_DISPLAY=wayland-N foot` with the socket it prints, or `DISPLAY=:N xclock` with the display its `X11 apps on :N` line names, which needs `xwayland-satellite` (Alpine and Arch package it; Ubuntu 24.04 does not, so test X11 apps in an Alpine container or the desktop image). Without a display (a cloud session), `xvfb-run -a cargo run -p edel-compositor --features winit -- --bench` works with Xvfb, Mesa (`libegl1`, `libgl1-mesa-dri`) and `libxkbcommon-x11-0` installed; a client such as `weston-simple-shm` makes it draw. The binary links libxkbcommon, libudev, libinput, libgbm and libseat (`libxkbcommon-dev libudev-dev libinput-dev libgbm-dev libseat-dev` on Ubuntu; `eudev-dev libinput-dev libseat-dev libxkbcommon-dev mesa-dev pkgconf` on Alpine); EGL is loaded at run time. In the desktop image greetd starts it; CI's `desktop-test` runs it under llvmpipe with `LIBGL_ALWAYS_SOFTWARE=1 LP_NUM_THREADS=0`, which virtio-vga needs (M4.1).

## Coming changes (roadmap)

`crates/testclient` is `edel-testclient` (M4.3): one window of `--size WxH`, `--colour RRGGBB` and `--title T`, drawn once and again only on resize, for CI's pixel checks; it exits when the compositor goes away. With `--layer top` or `--layer bottom` (M5.1a) it is a panel along that edge instead, on the top layer, its width 0 meaning the screen's and its height its exclusive zone. With `--workspace N` (M5.2b) it draws nothing: it shows workspace N over ext-workspace-v1 and prints the workspaces before and after, the shown one starred (`workspaces 1* 2 3 4`). With `--toplevels [TITLE]` (M5.2d) it lists the windows over wlr-foreign-toplevel-management, the focused one starred and one on no screen marked `-` (`toplevels one* away-`), and given a title activates that window and lists them again once it is focused. With `--sni` (M5.2e) it draws nothing: it registers a StatusNotifierItem on the session's bus, titled `edel test`, with a 22 by 22 pixmap of `#33aa66`, for the tray, and prints `activate X Y` or `context menu X Y` when shell-ui's tray clicks it. Only CI's images ship it. With `--recolour RRGGBB@FILE` (M5.2j-b4) it draws itself in that colour once FILE exists. With `--screenshot` and `--screencast` (M6.3) it draws nothing either: it asks xdg-desktop-portal for a screenshot (`screenshot URI file://...`) or to share the screen (`screencast stream NODE_ID WxH`), as an app does over the session's bus (`portal.rs`). With `--mpris` (M5.9d) it draws nothing either: it claims `org.mpris.MediaPlayer2.edeltest` on the session's bus as a player of "Night Drive" by "Lumen", 3:41 long, at 1:24, and prints `play pause`, `play`, `pause`, `stop`, `next` or `previous` as quick settings asks. With `--clipboard` (M7.13) the window is a clipboard user: key 1 copies `first copied text` and key 2 `second copied text` into the selection, and Ctrl+V pastes the selection, printing `copied TEXT` and `pasted TEXT` (or `pasted nothing`). Beside it, `edel-testheader` (M6.16, `crates/testheader`, a crate of its own so the test client builds where GTK is not installed) is one GTK 4 window with a header bar of its own, which prints its decoration layout, its close button's place and the close glyph's file whenever it lays its header bar out, for the own-bars case.

Make each change only in its step: M5.2g windows on the pointer's screen.
- Seam (ADR-011): screens and inputs stay behind the backend trait, as the DRM and winit backends are, so a paired device's screen or pointer (M7.10d, M7.10e) comes later as one more backend, never as a change to the window policies.
