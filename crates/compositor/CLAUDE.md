# The compositor

`edel-compositor`: windows, floating and tiling, title bars, outputs and effects (ADR-002), one of the two long-running processes of the Edel shell. Edition 2024, `rust-version = "1.85"`, GPL-3.0-or-later, `publish = false`. Built on smithay, pinned to `=0.7.0` with only the features in use.

## What belongs here

- Window management, outputs, input routing, title bars, effects and the frame loop. The panel, dock, launcher and notifications belong to shell-ui (M5); settings pages to Settings.
- No extension API, no theme engine, no second renderer (GLES only), no IPC daemon (ADR-002). Floating and tiling are two implementations of `layout::WindowPolicy`, chosen per workspace.
- Colours and sizes come only from `design/tokens.toml` through `tokens::Tokens`; never hard-code one in drawing code.
- Readers of files other releases write (tokens, later `system.toml`) are lenient: unknown keys and bad values keep the built-in value and are reported, never fatal (ADR-008). `tokens::check` is the strict reader for tests and builds.

## Layout

- `lib.rs`: the parts that need no display, tested with `cargo test`:
  - `tokens`: re-exports `edel::tokens` (the design tokens moved to the `edel` library in M5.1b, so shell-ui reads them with the same code).
  - `telemetry.rs`: render times and idle frames; `percentile` is nearest rank, the same rule as CI's desktop test (M4.1); `Summary` prints `frames N, render p50 X ms, p99 Y ms, idle frames Z`.
  - `layout.rs`: the `WindowPolicy` trait (`open`, `close`, `moved`, `arrange`, `rearranges`), `policies`, the table of every policy (one line each), `Workspace` (every policy follows the windows, the active one places them, `switch` and `next` change it), `Floating` (M4.3: centred, cascading `CASCADE` px off a window with the same centre, kept inside the area; the CI pixel checks depend on this rule) and `OutputLayout` (mode, scale snapped to 1/120, logical size). Policies place frames, not windows.
  - `layout.rs` also has `auto_scale` (M4.6a: the EDID rule) and `scale_120` and `snap_scale` (every scale in 1/120 steps from 1 to 4).
  - `cursor.rs` (M4.6b): `arrow`, the pointer's arrow drawn at any size, for when no xcursor theme is installed.
  - `effects.rs` (M5.11a): `Tier` (Lite, Balanced, Full), `starting_tier` (Lite on a software renderer such as llvmpipe, at most Balanced on battery, else Full) and `Deadline`, which drops one tier when 5 of the last 60 frames took over three quarters of the screen's refresh interval, then counts afresh and never raises it within a session; tested.
  - `animation.rs` (M5.11b): `Motion` (`appearance.motion`: full, reduced, off), `style` (how long windows open, close and slide, and the size they grow from, by tier and motion: the "Window animations" default row), `Anim` (eased out progress on the frame clock, never running long when a frame is late), `opening` and `closing` (alpha and size) and `Slide` (an offset from the window's place that shrinks to nothing, started from where the window is drawn when it interrupts another); tested.
  - `tiling.rs` (M4.5): `Tiling`, master and stack with the `gap` token; `tiles` is the geometry, tested for 1 to 6 windows.
  - `settings.rs` (M4.5): `Settings` (`tiling`, `preset`, `title_bars`, `outputs`, `motion`, `shortcuts`) from the machine's and the person's system file through `edel::system`, the person's keys winning; `policy` is `shell.tiling` if set, else the preset's (`edel::presets`, M5.1c); `load` reads both leniently and notes a preset this release lacks.
  - `frame.rs` (M4.4): server-side frames, drawn in screen pixels at the output's scale (M4.6a). `Insets` (the bar above, the border round the rest) turns a window's place into its frame's and back; `hit` says which part of a frame a point is on (title, maximize, close, an edge or corner within `GRIP` px); `paint` draws a bar described by a `Look` into ARGB pixels; `Text` is the title font (`fontdue`, the first of `FONTS` that loads) with its letters cached.
- `main.rs`: arguments (`--bench`, or `-- PROGRAM ARG...`), the tokens from `/usr/share/edel/design/tokens.toml`, else the built-in ones, and the backend: winit when `WAYLAND_DISPLAY` or `DISPLAY` is set, else DRM.
- `state.rs`: `Edel`, the Wayland state: compositor, shm, xdg-shell (offering maximize only), xdg-decoration, seat, data device, outputs, presentation time, one `Space` and the floating policy; `dirty` says something changed. A new toplevel waits in `unplaced` until its first buffer, then the policy places its frame and it takes the keyboard; `placed`, `outputs_changed` and `state_changed` keep the policy, the space and the state file in step, and a window that resizes itself or changes its title writes the state again; a window that drops its buffer leaves the screen and goes back to `unplaced`, to be placed anew when it draws again. `put` places a frame and tells the window its size and whether it is tiled; `relayout` puts every window where the active policy says, after a switch (`switch_policy`, Super+T's `toggle_tiling`), an output change or, in tiling, an open or close. `dragging` is set while a `WindowGrab` runs: never ask the pointer `is_grabbed` from code a grab calls, as it waits on its own lock. `listen` opens the socket.
- `outputs.rs` (M4.6a): each output's automatic scale (`set_auto_scale`, from the EDID in `drm.rs`), `Edel::apply_scales`, which gives every output its `outputs.NAME.scale` or automatic one, and `send_scale`, which tells a window's surfaces the scale (`preferred_buffer_scale` and `wp_fractional_scale_v1`; `wp_viewporter` lets them draw at it).
- `pointer.rs` (M4.6b): `Cursors`, what the window under the pointer asked for (a surface, or a shape name from `wp_cursor_shape_v1`), images from the xcursor theme (`XCURSOR_THEME`, else `default`) or the drawn arrow, at the output's scale, and frame callbacks for cursor surfaces. The cursor is a `Kind::Cursor` element, so the DRM compositor puts it on the cursor plane; `EDEL_SOFTWARE_CURSOR=1` draws it into the frame.
- `shellui.rs` (M5.1b): starts `edel-shell-ui` once the desktop is on screen, unless the session runs one program (the greeter), with the session's Wayland socket; a thread waits for it, and when it ends the compositor logs it and starts it again after 500 ms, giving up after 5 runs in a row shorter than 10 s; an image without it is said once.
- `shortcuts.rs` (M5.13a): `[shortcuts]` from both system files (merged in `settings.rs`, the person's over the machine's) laid over the defaults by `edel::shortcuts::resolve` and turned into keysyms: `bind` gives the bindings and notes, `find` the action for a key press (the Latin layout's keysym and exactly these modifiers), `changes` the `shortcut ACTION is KEYS` lines `reload_settings` logs. Close, tiling and terminal act (`program::open` starts foot with the session's socket and display); other actions bind nothing until their steps land, so their keys reach the app; a modifier tapped alone (the launcher's Super) waits for M5.3.
- `watch.rs` (M4.5): reads the settings at start and follows both files with inotify on the event loop (their directories, as writers rename); a change calls `Edel::reload_settings`, which switches the workspace when the policy (`shell.tiling` or the preset's) changed, lays the windows out again when `shell.title_bars` did and restyles the animations for `appearance.motion`.
- `decoration.rs` (M4.4): xdg-decoration (a window that asks for our bar or leaves the choice gets it, one that asks to draw its own keeps it), each window's `FrameData` in its user data (the bar's texture, redrawn only when its `Look` changes, the border buffers, the frame to go back to after maximizing), maximize and unmaximize, close, and `load_text`, which loads the font on a thread and redraws the bars when it arrives.
- `render.rs` (M4.4): `Element`, `Drawn` (an element as it is, or grown or shrunk about a window's centre) and `Edel::elements`, what both backends draw: the cursor, the top and overlay layers, the windows from the top, each with its popups, bar and border, faded, grown and moved as `animate.rs` says, closed windows' pictures at the depth they had, then the bottom and background layers.
- `animate.rs` (M5.11b): `Animations`, what is opening, sliding and closing, on a clock started with the compositor. `put` and maximizing call `Edel::slide`, which starts a slide when the window is already on screen elsewhere (a window still opening grows in where it ends up instead, and `unmaximize_under` stops the slide, as a person's drag follows the pointer); the first map calls `opened`; `remember_picture` keeps each drawn window's surface textures, so `snapshot_closing`, called when a toplevel is destroyed, can fade out a client that already exited; `restyle` follows the tier and `appearance.motion` and logs `animations at tier T, motion M: open X ms, close Y ms, slide Z ms` when they change. While `running`, the DRM backend arms a timer for one refresh interval that marks the screens dirty, so animations step with the display and never faster, even on a virtual GPU that shows a frame the moment it is queued; winit asks for another redraw.
- `tiers.rs` (M5.11a): the session's tier: `start_effects` reads the GL renderer's name once the renderer exists (`renderer_name`), the battery from `/sys/class/power_supply`, or `EDEL_EFFECTS=lite|balanced|full`, logs `tier=NAME (why)` and writes `tier` to the state file; `frame_drawn` feeds each drawn frame and the screen's refresh interval to the `Deadline` and logs a drop, after which `restyle` shortens the animations.
- `layers.rs` (M5.1a): `zwlr_layer_shell_v1`, for shell-ui's panels and anything else that draws one. Each screen's layer surfaces live in smithay's `layer_map_for_output`, placed by `LayerMap::arrange` from their anchors and margins; a commit arranges the screen and sends the first configure; `window_area` is the first screen less the exclusive zones, where windows open, tile and maximize (`output_area` stays the whole screen, for absolute pointers), and a change to it lays the windows out again; `under` meets the top and overlay layers before the windows and the bottom and background ones after; a click on a layer that takes the keyboard gives it the keyboard; layers hear their screen's scale and get frame callbacks like windows; the state file lists them as `[[layers]]` (namespace, layer, output, place).
- `input.rs`: keyboard, pointer, scrolling and pens (`zwp_tablet_v2`, M4.6b) for both backends (relative and absolute motion, click to focus and raise; `under` finds the frame part or surface at a point; a bar drags, double-clicks to maximize and its buttons act on release; edges resize; Super with the left or right button starts a move or resize; the keys `shortcuts.rs` binds act) and the terminal Ctrl+Alt+F1 to F12 asks for.
- `grabs.rs`: `WindowGrab`, one pointer grab for moving and resizing (`resized` keeps the opposite edges and a 96x64 minimum; a maximized window lets go after 8 px); it hands the final place to `Edel::placed` when the button is released.
- `statefile.rs`: the writer thread of `/run/edel/session/state.toml` (only outside a session it does nothing); the newest state wins. `replace` writes a file whole under `NAME.new` and renames it over the old one, never opening a file through a link; the health file `ready` is written the same way, since the greeter's compositor and the person's replace each other's files (M4.7b).
- `program.rs` (M4.7b): `edel-compositor -- PROGRAM ARG...` starts the program once the first screen has shown a frame (in the development window, from the first turn of the event loop), with `WAYLAND_DISPLAY` and the X11 display as `DISPLAY`; a thread waits for it, and when it exits, or cannot start, the compositor stops. greetd's greeter is `edel-compositor -- foot agreety --cmd 'dbus-run-session -- edel-compositor'`. `open` starts a program in the session the same way, without ending it, as Ctrl+Alt+T does with foot (M5.13a).
- `drm.rs` (M4.2b, M4.6c): the backend for real screens. A libseat session opens the primary GPU (`primary_gpu`, else the first); GBM, EGL and `GlesRenderer`; `Gpu::scan` lights every connected screen the settings want (a `Screen`: its output, a CRTC of its own, a `DrmCompositor`) at `outputs.NAME.mode`, else its preferred mode, else the first it lists, darkens screens unplugged or turned off, and places them with `place_screens`; it runs at start, on udev's change events, when the seat comes back and when `Edel::screens_changed` is set by a change to `[outputs]`; libinput on the session. Windows open on the first screen (`output_area`) until M5.2. Each screen draws when it is dirty (`Edel::dirty` marks them all) and its last frame's vblank has come; on the vblank, presentation feedback goes to clients, each screen's first frame logs `edel-compositor: output NAME WxH ready`, and the first screen to draw writes `/run/edel/session/ready`, the desktop's health (M4.8). With no screen connected at start the compositor stays up, writes `ready` as `no screen connected yet; waiting for one` and lights the screen udev later reports, so a desktop booted without its screen is never restarted by the boot guard. A timer armed by the first frame after a quiet spell logs the telemetry once the screen has been still for 2 s, so nothing wakes while idle. Pausing the session (another VT) pauses DRM and libinput; activating resets the compositor's state and redraws.
- `xwayland.rs` (M4.7): X11 apps. `listen` takes the first free X11 display (its lock file `/tmp/.XN-lock`, as X servers write it, taken over when its process is gone; its socket in the abstract namespace and in `/tmp/.X11-unix`) and logs `X11 apps on :N`, if `xwayland-satellite` is on the `PATH` (feature `xwayland`). When the first X11 app connects, `xwayland-satellite :N -listenfd A -listenfd B` starts with copies of the sockets (`rustix::io::dup`, so they survive exec), runs XWayland on them, and turns X11 windows into ordinary Wayland windows, so they get our bars, policies and keyboard focus with no X11 code here. While it runs the sockets' sources rest; a thread waits for it, and when it stops, apps still waiting are turned away and the sockets wait again, so the next X11 app starts it anew and a crash never loops. The lock and socket go when the compositor exits. No smithay XWayland feature: smithay 0.7 opens XWayland's sockets itself, so it could not start on demand.
- `winit.rs`: the development backend. A frame is drawn only when `dirty` is set (a commit, a new or closed window, input that focuses, a resize), so an idle desktop draws nothing; `--bench` stops after 5 s and prints the telemetry.

## Running it

On a desktop with X11 or Wayland: `cargo run -p edel-compositor`, then `WAYLAND_DISPLAY=wayland-N foot` with the socket it prints, or `DISPLAY=:N xclock` with the display its `X11 apps on :N` line names, which needs `xwayland-satellite` (Alpine and Arch package it; Ubuntu 24.04 does not, so test X11 apps in an Alpine container or the desktop image). Without a display (a cloud session), `xvfb-run -a cargo run -p edel-compositor -- --bench` works with Xvfb, Mesa (`libegl1`, `libgl1-mesa-dri`) and `libxkbcommon-x11-0` installed; a client such as `weston-simple-shm` makes it draw. The binary links libxkbcommon, libudev, libinput, libgbm and libseat (`libxkbcommon-dev libudev-dev libinput-dev libgbm-dev libseat-dev` on Ubuntu; `eudev-dev libinput-dev libseat-dev libxkbcommon-dev mesa-dev pkgconf` on Alpine); EGL is loaded at run time. In the desktop image greetd starts it; CI's `desktop-test` runs it under llvmpipe with `LIBGL_ALWAYS_SOFTWARE=1 LP_NUM_THREADS=0`, which virtio-vga needs (M4.1).

## Coming changes (roadmap)

`crates/testclient` is `edel-testclient` (M4.3): one window of `--size WxH`, `--colour RRGGBB` and `--title T`, drawn once and again only on resize, for CI's pixel checks; it exits when the compositor goes away. With `--layer top` or `--layer bottom` (M5.1a) it is a panel along that edge instead, on the top layer, its width 0 meaning the screen's and its height its exclusive zone. Only CI's images ship it.

Make each change only in its step: M5.2 the minimize button; M5.10 the compositor greeting people itself.
