# The modules of Settings

What each module holds, one bullet per module (moved here from [CLAUDE.md](CLAUDE.md) by M6.17, line 11, so the rules a session reads stay short). Read the bullets of the modules you change before editing them, and keep them true in the same PR: a new module adds its bullet, a removed one takes its bullet out, a changed one edits only its own bullet.

- Pages name the feature they talk to (`Page::needs`) and are hidden when the machine has no `features/NAME.toml` in `edel::features::DIR` (`pages_in`); tests hide one in a temp directory and fail when a page names a feature with no file under `features/`.
- `main.rs`: the application (the sidebar lists each group's heading above its first shown page, About last under none: `sidebar_rows` and `Row` are the plain list, a heading is not selectable, not focusable and hides while the search has text, and the sidebar logs `sidebar group NAME X+Y+WxH` for CI, M5.32b; the installer's row, first on a stick, is tinted in the accent with a gap under it (`edel-install-row`); `edel-settings --page NAME` opens a page at the start, Appearance, the first page, without one, by its section or title or the start of one of them, `displays` or `display`; `edel-settings --welcome` opens the Welcome instead (`welcome.rs`, M6.12), and the two cannot be given together (`start_page` refuses both, as `Start`); `edel-settings --app ID` opens the Apps page with that app's page open (M6.14a) and cannot be given with either; a name no page has is refused with the pages there are, `start_page`; a page opened by name gives the keyboard to its main control, and GTK itself is given only the app's id; `APP_ID`, which `features/settings/usr/share/applications/APP_ID.desktop` is named after; a test holds them together) and the window: a plain `gtk::ApplicationWindow`, not libadwaita's, so the compositor draws its title bar with the person's buttons (GTK asks through KDE's server decoration protocol); an `AdwNavigationSplitView` in an `AdwBreakpointBin` with a 204 px sidebar (`SIDEBAR`), as the mockups draw it: a search field (`finds`: a page's title or its rows' titles; Ctrl+F; Return opens the first found) and the pages with our icons; below 600sp (`NARROW_SP`) the split view collapses and a page shows a way back. Pages are built when first shown and kept. A row's key or title names its page too (`layout.panels`, `panels`), and that row's control takes the keyboard (`widgets::set_asked_row`, which `panels.rs` reads when the page shows).
- `style.rs`: `Theme`, the tokens in the scheme the desktop shows (the settings portal, through `adw::StyleManager`), read through `edel::tokens::on_this_machine` (M5.12b1: the person's accent and colours, and the stylesheet is written again when a settings file changes them, watched with `gio::FileMonitor` as the other pages watch theirs), and `css`, the one stylesheet written from them, again when the scheme changes, when `watch`ers redraw too; only spacing is written here, every colour, radius, the font and the text's size are the tokens' (`window`, `card`, `line`, `panel`, `title_text`, `title_text_unfocused`, `accent`, `shadow`, `title_close_hover` for problems, `radius_*`, `text`, `font.interface`). A test fails when a colour is written here.
- `touch.rs` (M9.6): touch mode. `follow` reads `edel::touch`'s key from the settings portal once (`ReadOne`, async), follows `SettingChanged`, and marks the window `edel-touch` while it is true, which `style::css` grows to `edel::touch::TARGET` rows; with no portal it stays a pointer's size. Logs `rows sized for touch` and `rows sized for a pointer` when that changes.
- `icon.rs`: `Icon`, a GTK symbolic paintable of one of `design/icons/`, drawn by `edel::icons` (feature `icons`) and painted in the colour of the text around it, so selection and the scheme recolour it; `image(name, size)` centred at its size.
- `widgets.rs` also holds `ChangeBar` (M5.6a): changes apply at once, so the desktop is the preview; once the person's file differs from what it was when the page opened, a pill floats up with Undo (`Files::restore` puts the file back) and Keep; Save as preset joins it with M5.17, and the timed undo for pages whose changes can strand a person (Displays) is not built yet.
- `widgets.rs`: the building blocks every page is made of (M5.8d added `Hero`, `big_button`, `banner` and `disclosure`, a fold-out that starts closed), and with `card.rs`, `icon.rs`, `preview.rs` and `style.rs` the building blocks; most other modules still call GTK directly, so a new page uses these blocks (ADR-004's own look decision; another toolkit would be these again, M10.8): `page` (title, what the page is for, a line for problems, scrolling, at most `PAGE_WIDTH`), `section` (a heading with where its value comes from, Reset and Copy as command), `heading`, `group` (a card of rows), `row` (title, a line under it, Reset, Copy as command, the control), `value_row`, `copied`, `action` (a button for something to do now) with `output_row` and `say` (what a command said, in a fixed-width font, red when it failed), `pick_file`, `picture_card` (a choice drawn as a picture above its name, with a check when chosen, shared by the presets' and the wallpapers' cards, M5.10c4c), `folding` (a group told whether it is narrower than the window's breakpoint, so it lays itself out for its width; never an `adw::BreakpointBin` inside a page, which has no height of its own and showed nothing on a page taller than the window), `Choice` (a value from a few, in a list; `Choice::searchable`, a long list with a search line above it, the list filtered as it is typed and Return taking the first left; `set_width` and `chosen_text`), `step_heading` (a numbered step's heading, its number in an accent disc) and `Segments` (a value from a few, all in view, one click). `Line` (M6.14c, moved from `region.rs` with its helpers `set_words`, `reset_words`, `root_command`, `exit_text` and `monitors`, which the Region and Location pages share): a row's line from `edel::key_help`, then where its value comes from, Reset and a refused change's message. M5.12b6b moved `pill`, `menu_item`, the New card (`new_card`), the name dialog (`ask_name`) and the delete question (`ask_delete`) here from `lock.rs`, so the lock's looks and the Appearance page's themes share one copy. M6.18 added `confirm`, every yes or no question in our own look, now built on `prompt` (a `Prompt`: a small modal `edel` window with the alert dialog role: the question, a code shown large (`edel-code`, read figure by figure), a line under it, Cancel as the default and Escape to close, and the act if any, red when `danger`), which returns `Prompted` so a caller can `dismiss` a question that went away; `ask_delete` calls `confirm`; Settings shows no `gtk::AlertDialog`. Every small dialog's window is `modal` (modal over its page's window, a title, a width, not resizable, plus what one dialog adds, such as the `edel` class or a role), its content `dialog_body` and its buttons `dialog_buttons`, which `ask_name`, `confirm`, `ask.rs`, `shortcuts.rs` and `themes.rs` share (2026-10-17 review).
- `preview.rs`: (M5.9l) `list_area`, the Notification list's three pictures. A preset's picture on its card, drawn with cairo from the preset's file (its bars and docks, its windows floating or tiled with the buttons on its side) in the tokens' colours, drawn again when they change. `panels` draws the bars and docks of a list of panels, and the Panels group's picture (`panels_area`, M5.31d) is the same screen with each widget as a mark (`widget_marks`) and no windows.
- `files.rs`: `Files` (the machine's file and the person's), `low_latency` and `low_latency_without_mine` (M7.6b, the key as the compositor reads it, with profiles), `layout()` (each Layout key's value: the person's over the machine's, then the preset, then the release: `Layout::value`), `choose` (a key written, or taken out when it is what would apply without it), `set`, `source`, `shortcut` (an action's keys as the desktop follows them, for a row's text), `title` (a preset's name as people read it). Tested on files in a temp directory: never a default written, the file equal to `edel settings set`'s, a refused value's text equal to the command's.
- `themes.rs` (M5.12b6b, part c2): the Appearance page's theme card, with `Edit`, the one kind of change the pictures make (`Add`, `AddTo`, `MoveTo`, `Remove`), written by `Card::edit` through `edit_person` and the library's writers, which logs `themes pictures added N to NAME`, `themes picture removed from NAME` or `themes picture moved from A to B` for CI, and shows the result; each own theme's tile takes a drop of a picture's reference (a `gtk::DropTarget` on the tile, built-in tiles take none), and `new_tile` is the dashed tile the sheet's Add pictures uses.  first on the page under its intro (`card`, built by `layout.rs`'s `appearance` arm). `Shown::of` reads the theme in use from the person's file as it is (not `Files::person_file`, which lays the theme under the values), the machine's name only when the person names none. The theme line: the title, Built in theme or Your theme, the first three pictures as a `gtk::Fixed` of thumbnails, `N pictures ›` (a `gtk::Revealer` sheet under the line opens, not a popover: a popover is a window of its own and CI clicks by the places the window logs), `Changed: WHAT` (`changed_words`, the rows' plain names through `rows::plain`, at most two then "and N more"), and, only while something is changed, Reset (`themes::reset_text`) and Keep as new (`widgets::ask_name` with `themes::copy_name`, then `save_text`); the More menu has Duplicate, Rename… and Delete… (own themes only; Delete is red and chooses Edel in the same write, as the theme in use cannot be deleted). The styles are three `gtk::ToggleButton`s over `Look`s drawn with cairo (`draw`, `scene`, `cover`, `window`): the theme's first picture in each scheme (`picture_of`, cover-fitted, the tokens' background where there is none), with a window and the panel's strip over it; Automatic is `Sides::Split`, light top left and dark bottom right. A style writes `appearance.mode` with `Files::choose` (`light`, `dark`, `auto`, the key table's names; `auto`, not `automatic`) and never makes the theme Changed. The themes row is a horizontal `ScrolledWindow` of tiles (the built-ins, then the person's own, each a split picture with the Built in pill, then the New card from `widgets::new_card`, whose menu offers From the theme in use and Blank, `themes::blank_text`); a tile writes `appearance.theme` with `Files::choose_over` (taken out for `edel`, the default). Theme tokens changing redraws the styles (`Theme::watch`). Logs: `edel-settings: appearance group places style L D A, pictures X+Y+WxH` (`log_style`, which scrolls to the styles when asked for `appearance.mode`) and `edel-settings: themes places NAME X+Y+WxH, ..., new X+Y+WxH` (`log_themes`), and `edel-settings: theme NAME changed KEYS` (the words of the changed keys, or `nothing`; logged when the line changes, `show_now`). Tested: the changed words (one key, three keys, a family once). The name and blank-theme rules are tested in `edel::themes`. Export and import (M5.12b6): the More menu's Export… and Import… (after Rename…, every theme; Import… as the New menu's, asked by Alimardon on 2026-10-12) asks where to save `NAME.edeltheme` in a `gtk::FileDialog` and writes it with `edel::theme_file::export`, a failure in the problem line; the New menu's Import from a file… (after Blank) opens a dialog filtered to `*.edeltheme` and a file dropped on the themes row (`gtk::DropTarget`, `drop_file`) does the same. `offer` reads and checks the file with `theme_file::read` and `plan` (nothing written yet): a file that does not check shows its message in the problem line, and a good one opens `import_dialog`, its title, "N pictures" and what it sets in plain words, with Cancel and Add theme (the default); Add theme (`add_import`) copies the pictures, then one `edit_person` write adds the table and sets `appearance.theme` to the name. Logs: `edel-settings: themes exported NAME to FILE`, `themes import shown TITLE`, `themes imported NAME`.
- `wallpaper.rs` (M5.10c4c, M5.12b6b, M5.12b6 part c2, M5.12b5): `reference_picture_at` and `title_of` (pub) are the thumbnails and titles the Workspaces page's rows share; the pictures sheet of `themes.rs`'s theme card, under the title `Pictures in THEME`: the theme's own pictures first, each a reference card (a wallpaper's name, a picture's path or a colour, `reference_picture`) with its menu (`chrome` and `menu`: Add to this theme for a picture the theme lacks, Add to theme and Move to theme for each of the person's other own themes by title, hidden when there are none, and Remove for the theme's own), shown on hover and focus or by a right click, and a drag source carrying the reference; then `More wallpapers` and every other wallpaper in `places::WALLPAPERS_DIR`, then None, Your picture, Colour and the Add pictures tile (`card(content, problem, theme, title, first, sheet)`, with `Sheet` holding the other themes and `run`). A card per wallpaper in `places::WALLPAPERS_DIR` (its picture the light half and the dark half side by side, `thumbnail`), then None, Your picture (`pick_file`, a JPEG or PNG) and Colour (`gtk::ColorDialog`, written `#rrggbb`); each click writes `appearance.wallpaper` with `Files::choose_over`, a value that applies with nothing chosen is `release_value` (the default wallpaper when carried, else none) and `shown` is what applies, with the group's source line, Reset and Copy as command. `show` follows the files; asked for by its key, the group scrolls to the top, takes the keyboard and logs `edel-settings: wallpaper group places NAME X+Y+WxH ..., reset X+Y+WxH` for CI. Tested: the release, the shown value and the kinds of value. Your picture (M5.10c4d) opens a multi-select dialog: one picture writes `appearance.wallpaper` and sets `appearance.mode` light or dark by its mean brightness (`luminance`, read from a 64 px copy), two write the brighter as `appearance.wallpaper` and the darker as `appearance.wallpaper_dark` (`apply_pick`, `pick`, `unpair`), and the card's slot shows the pair's halves (`halves`, which `thumbnail` shares); more than two, or an unreadable picture, writes nothing and says why.
- `shape.rs` (M5.12b2c, redrawn after M5.12b2c): the Appearance page's Shape group, after the Colours group: a section with its source line, Reset (takes the six keys out) and Copy as command, then the picture first, 180 px tall (`draw`): a box with `radius_menu` corners, filled with `card` and edged with the page's hairline, holding a desktop in `background` inset 16 px, two tiled windows (`frames`, `draw_window`) and a panel strip 14 px high in `panel` at `panel_opacity`. Each size is the slider's value scaled by the box's height over 800 (`scale_of`; `px` gives at least 1 px above 0, `bar_px` a title bar at least 6 px): the title bars in `title_bar` and `title_bar_focused` with three button dots at their right, the bodies in `window`, the borders in `window_border` and, for the focused window, `window_border_focused` with its gradient. Then the six rows as one grid (`plan`, `lay_out`): the title with its line (the border's `Its colours are in Colours: Window border focused`, then where the value comes from), a `gtk::Scale` over its key's `settings::whole_range` at 220 px, its value at 96 px right-aligned with tabular figures (`words`: `10 px`, `Square`, `None`, `Same as gaps` while the gaps at the edge are unset, `100 %`), and Reset and Copy as command in an actions column whose copy shows while the pointer is over the row (`reveal_copy`, `edel-shape-actions`). Below the narrow width (`crate::NARROW_SP`, `widgets::folding` around the grid calling `lay_out`; the card is what it measures) each slider goes under its title at full width, its value at the end. Each slider is one key of the person's file, read from the value the files give (`Tokens::built_in().with_shape`); a drag writes its key once it settles (250 ms, as Sound's volume), through `Files::choose_over` so the release's value is taken out, never written, and logs `shape KEY VALUE written` or `taken out` for CI. Asked for by one of its keys, the page scrolls the group to the top and gives the keyboard to that slider; once two frames agree it logs `shape group places radius X+Y+WxH, gaps ...` for CI. Tested without GTK: the words at their ends, the sliders' ranges against the key table, the picture's frames inside the area above the panel with the gap between them at the scaled gaps value and title bars of at least 6 px (the release's, the largest and the smallest values), the scale of the sizes, each row's cells once, and the grid's columns wide and narrow. `EDEL_SETTINGS_PNG=DIR cargo test -p edel-settings shape` writes the picture as PAM files (cairo here has no PNG writer; ImageMagick converts them) for a look.
- `cursor.rs` (M5.12b5 part A): the Appearance page's Cursor and icons group, after the Text group and before the Shape group: a section with its line and source line, Reset and Copy as command, then a card with the Cursor row (a `widgets::Choice` of `settings::cursor_themes()`, `default` first, written with `Files::choose_over` against `default`), the Icons row (M8.21 part g, `appearance.icon_theme`, the same `Theme` row over `settings::icon_themes()`, `Edel` first) and two sliders over their keys' ranges, Cursor size (`appearance.cursor_size`, 16 to 96, shown as `24 px`) and Icon size (`appearance.icon_size`, 75 to 150, `As made` at 100). The sliders and the places logger are `shape.rs`'s, as Depth's are; the places log is `cursor group places cursor_size ..., icon_size ..., cursor_theme ..., reset ...` and each write logs `cursor KEY VALUE written` or `taken out`.
- `depth.rs` (M5.12b3): the Appearance page's Depth group, after the Shape group: a section with its line and source line, Reset and Copy as command, then a card of five sliders over their keys' ranges (`settings::DEPTH_KEYS`): Window opacity and Unfocused windows (`appearance.window_opacity` and `_unfocused`, 20 to 100 percent, `Opaque` at 100), Shadow size (`appearance.shadow_size`, 0 to 64 px, `None` at 0), Shadow darkness (`appearance.shadow_darkness`, 0 to 100 percent, `None` at 0) and Glass blur (`appearance.blur`, 0 to 100 percent, `Sharp` at 0, the glass behind see-through panels), whose release value is 50. The sliders, the grid that folds them at the narrow width and the places logger are `shape.rs`'s (`slider`, `plan`, `lay_out`, `log_places`), so both groups look and fold alike. Each slider starts at the value the files give (`Tokens::built_in().with_shape`, the shadow's darkness the shadow colour's alpha, rounded); a drag writes its key once it settles (250 ms) through `Files::choose_over`, the release's value taken out, and logs `depth KEY VALUE written` or `taken out`. Asked for by one of its keys, the page scrolls the group to the top and gives the keyboard to that slider; the places log is `depth group places window_opacity ..., shadow_darkness ..., reset ...` for CI. Tested without GTK: the words at their ends, the ranges against the key table, the release values, the rows on the Appearance page.
- `text.rs` (M5.12b5): the Appearance page's Text group, before the Shape group: a sample sentence in the chosen font at the chosen size, the interface font and the monospace font as drop-downs of pango's families (sorted, the release's first and marked "(default)", each name drawn in its own face, the monospace list only monospace families), and Text size, a slider from `settings::whole_range` shown as "Default" at 100. Each is one key of the person's file, written with `Files::choose_over` against the release's value (taken out, never written) after a drag settles (250 ms, as Shape's sliders); Reset and Copy as command per row and for the group. It logs `edel-settings: text group places font ..., monospace_font ..., text_size ...` for CI and `text KEY VALUE written` or `taken out` on each write.
- `motion.rs` (M5.12b4): the Appearance page's Motion group, after the Shape group: a section with its source line, Reset and Copy as command, then a card of three rows: Motion (`appearance.animations`, Full, Reduced and Off as `Segments`), Animation speed (a slider over `whole_range` with its words at the end, `Slower · 0.5x`, `As made · 1x` or `Faster · 2x`, from `words` and `factor`) and Feel (`appearance.animation_curve`, Smooth, Snappy and Springy). Each choice is one key of the person's file through `Files::choose_over`, so the release's value is taken out, never written, and a drag writes once it settles (250 ms); each logs `motion KEY VALUE written` or `taken out` for CI. Speed and Feel are insensitive while Motion is Off. Once laid out it logs `motion group places animations X+Y+WxH, animation_speed ..., animation_curve ...` for CI. The rows are found by search too, which matches a row's values as well as its title, so `spring` finds Feel. Tested without GTK: the words and the factor, the ranges, the rows on the Appearance page.
- `colours.rs` (M5.12b1c): the Appearance page's Accent and Colours, after the Style row: the accent as swatches (`tokens::accents()` in the file's order, one card with no words of its own, as the heading's line names the accent, then Wallpaper, drawn with the wallpaper's colour in two halves or the graphite grey while it is not known, and Custom, which opens `widgets::choose_colour`), each written by `Files::choose_over` (blue is taken out, never written) and logged for CI (`accent group places`); under the swatches, the High contrast row (M6.9): one switch for `appearance.contrast`, written with `Files::choose_over` against `normal` (taken out when normal is what applies; a machine's `high` is overruled by a written `normal`), with Reset and Copy as command and the line `Strong edges and the plainest colours, for text that is easy to read` before where its value comes from, logged `edel-settings: contrast appearance.contrast high written` or `taken out` for CI; then one row per colour the files set, both schemes and each scheme's own, each titled by `readable` (`panel_text` reads Panel text) with Reset and Copy as command, written and taken out with `Files::set` so a refused pair shows its message under the row and in the problem line; and the Add a colour row (names from `tokens::COLOUR_NAMES`, Both, Light or Dark, a colour button). `listed`, `key_for`, `swatch_of` and `readable` are tested without GTK. The colour rows are built again only when their keys change. M8.21 21k2: `accent_title` keeps the wallpaper's and a custom colour's words and takes the nine accents' from `edel::tokens::accent_title`.
- `desktop.rs` (M8.21 part 21j1): the Desktop widgets group on the Appearance page, after Motion: one switch for `appearance.widgets` (the clock and the date over the wallpaper, under the windows), on when the desktop's list is not empty. On writes `lock_screen::desktop_default` through `widgets_value`; off takes the person's line out, and writes `[]` only where the machine's file still gives a list. Its row is `rows.rs`'s `appearance.widgets`, and the round trip is tested without GTK through `edel::settings::desktop_widgets_in`. M8.21 part 21j2: its Edit button, shown while there are widgets, asks shell-ui for `EDIT_DESKTOP` through `panels::ask_editor`, as the Lock screen page's Customize does.
- `lock.rs` (M5.10c5c, M5.32b, M5.10c7b): the Lock screen page, a gallery of looks, each a preset of its own (its widgets and its wallpaper, set inside the look on the lock). The Looks section (`widgets::section`) holds a `gtk::FlowBox` of cards, at most 3 a line, 16 px apart: the three built-in looks (`lock_screen::LOOKS`) then the person's own by name (`card_list`, each picture drawn with cairo from `lock_screen::applied` of that look alone, 256 by 160 px as the least, `look_picture`, drawn by `draw_look`), each a `look_card` (M5.10c7b: the picture alone, with nothing round it; `style.rs`'s `edel-look-card` rules ring the chosen one 2 px, 3 px outside the picture, and hover a thin line; the picture fills the card's width and its height follows at 16:10, set by a tick, as a flow box measures children without the width), its name and an In use pill (`pill`, `edel-in-use`) on the row under it, and on a built-in look's picture a frosted Built in badge (`edel-built-in`); a look of the person's own carries no word; last the New look card (`new_look_card`, a dashed picture as tall as a look's, and "From the look in use"). `draw_look` paints the background (a backdrop look's gradient at 160 degrees, a wallpaper's corner to corner with a soft glow), the clock and date as words, the person as a glass pill with a disc over it when tall enough, and the other parts as frosted plates from the tokens' lock colours; `EDEL_LOOKS_PNG=DIR cargo test -p edel-settings the_looks` writes `looks.pam`, and `looks.png` beside it with ImageMagick. A click on a card chooses the look (`choose_look`, which the library's `lock_screen::chose_text` writes, taking the person's widgets and wallpaper lines out, M5.10c7h); New look and Keep as a look make a look of the one in use (`save_as_look`, the library's `lock_screen::saved_as_text`, named by `lock_screen::new_look_name`). The person's file is written as one text with `Files::write_person`; the merged lock settings are `Files::lock`, which is `lock_screen::lock_over`. Under the gallery, the look in use (`widgets::folding`, stacked when narrow): a small picture of it (96 by 60), its title with the In use pill, a line (`look_line`: Built in, Yours, or Changed over LOOK on the command line, which also shows Keep as a look), Customize, the one filled button (`panels::ask_editor` with `edel::panel_edit::EDIT_LOCK_SCREEN`, which writes nothing itself) and a More menu (`gtk::MenuButton`) with Duplicate, and for the person's own looks Rename (`ask_name`, `renamed` through `lock_screen::looks_value`) and Delete (`ask_delete`, `widgets::confirm`, Cancel the default). Then "On every look": the notifications switch. Removed from the page: the Background tiles and the Clock and date group, which the look's parts and background change on the lock now. `parts_text` writes the widgets with `edel::lock_screen::widgets_value`; the keys are `lock_screen::WIDGETS`, `LOOK` and `WALLPAPER`, and `lock_screen.looks` is `OWN_LOOKS`. `--page lock_screen.look` scrolls the gallery to the top and gives the keyboard to the chosen card; `--page lock_screen.wallpaper` or `.widgets` scrolls the look in use to the top and gives the keyboard to Customize. The places are logged as `lock_screen group places NAME X+Y+WxH ..., new X+Y+WxH, reset X+Y+WxH` for CI. Tested without GTK: the card sizes, the card list and what each draws, the lines under the look in use, the values read back through `edel::settings::read`, renaming and deleting through `looks_value`, and the parts' round trip.
- `look_pictures.rs` (M5.10c7c): the lock screen's look pictures, which the Lock screen page's cards and the look in use show in place of Settings' own drawing. `key` names a look's picture by an FNV hash of its parts, its background, its dim (M5.10c7g), the wallpaper that applies, the scheme and the tokens (`Inputs`, read from the files and the theme), so a picture is kept while it would draw the same. `want` lays the file over the drawing when it is in the person's folder (`places::look_pictures_dir`), else queues `edel-shell-ui --look-picture NAME --out FILE --width 480` on GIO's thread, two at a time, and lays it over when it is there (the frame remembers the key it waits for, so a late picture for another look is left out); a shell-ui not on PATH draws nothing. `show_drawn` takes a picture off again, and `prune` deletes the pictures the page no longer shows. The drawing stays until a picture is there, so the page never waits; logs `edel-settings: lock_screen picture NAME ready`. Tested: the key changes with what a picture shows.
- `default_apps.rs` (M6.10): the Default apps page, one row per `[default_apps]` key (`apps::DEFAULT_APP_KEYS`, titled by `rows.rs`). Its choice offers Automatic, which takes the key out and names the app it opens when one is installed, then the installed apps of the role's kind, and the key's own value when no listed app is it. The apps are read once when the page opens; a choice is built anew, after the callback that asked, only when what it offers changes. CI reads `edel-settings: default apps places`.

- `cmd.rs` (M5.8c; M8.14): `edel_as_root_or_self(args)` runs `edel` as root where doas allows and as the person when doas refuses (`or_self`, tested on `Outcome`), so the update check keeps its record; `edel(args)` runs the `edel` tool and gives an `Outcome` (exit status, output, message; `shown()` is what a person reads: the output on success, else the message as `edel` wrote it), and `line(args)` the command for Copy as command. Called from `gio::spawn_blocking`, never from the thread that draws. Changing the machine runs as root through `doas` (M6.5): `edel_as_admin` gives the administrator's password to `edel --password-stdin`, which the Updates page's dialog (`ask.rs`) asks for, and a refusal is shown as it is. `edel_as_root(args, input)` (M6.6a) runs `doas -n edel ARGS` (or `edel` when Settings runs as root) with optional standard input, for the installer page, whose stick account doas lets run `edel` with no password. `set_and_apply_as_root(words)` (M6.14c) runs a machine key's `edel settings set` or `reset` as root, then `apply` when that worked, for the Region and Location pages.

- `ask.rs` (M6.5): the password dialog of the Updates page, built like the Shortcuts page's Change dialog from our widgets: a `PasswordEntry`, Cancel and the button, with the words an `Ask` names (`n_` marked). It runs `cmd::edel_as_admin` on a thread, the password read once from the entry and cleared there, and a wrong password (exit status `edel::exit::WRONG_PASSWORD`, 67, in the outcome) keeps the dialog open and says so; `running(true)` and `running(false)` tell the page to show its busy phase or go back; CI reads `edel-settings: update asked, exit N` (`rollback asked` for going back). An `Ask` can list `detail` lines under its prompt, ask for the computer's name (`name`, matched by `edel::install::is_machine_name`, the button waiting for it and a password, logged as `edel-settings: COMMAND ready true|false`) and draw its button in the danger colour (`danger`), as Erase everything does (M8.38).

- `updates.rs` (M5.8c, remade in M5.8d at Alimardon's ask of 2026-10-08, drawn as the approved board of 2026-10-11, M5.32): what an updates page is everywhere, in that order. Under the hero, a card for the version kept ready (shown only when `status::view` has a rollback: its icon, `{version} is kept ready`, and a grey Roll back button that asks twice, 5 s, as `Click again to roll back`; its tooltip says `edel rollback`). - `status.rs` (M5.8d): the Updates page without a toolkit, all tested: `Status::parse` (`edel status`' slots; `pending`, a version waiting for a restart or a rollback doing so; `rollback_to`), `parse_check` (`edel update --check`'s `available:`, `newer:`, `released:` and `size:` lines), `Phase` (idle, checking, up to date at a time, available, installing, installed, going back, restarting, failed) and `view`, the one `View` each state draws: icon, headline, line, leading button, Go back's version, the What's new card.
