# Settings (`edel-settings`)

Settings, the app for every setting (ADR-008, roadmap M5.6): GTK4 and libadwaita, as ADR-004 chose for our apps, the one app of ours on them, drawn in our own look (ADR-004's own look decision of 2026-10-06): every colour, corner and font from the design tokens, our own icons, the compositor's title bar, never GNOME's look. Match `docs/mockups/` where they show a page; where they are silent, build from the blocks in `widgets.rs`. Edition 2024, `rust-version = "1.85"`, GPL-3.0-or-later, `publish = false`; not a default member, so `cargo run` builds only `edel`.

## What belongs here

- A page per section of the settings file, named and ordered by `edel::settings::PAGES`, the table `edel settings` prints, so the app and the command never disagree (ADR-008's same names decision). A page is added in the step that brings its section (M5.7 to M5.10, M5.12; Layout, Displays, Sound, Network, Bluetooth, Notifications, Shortcuts, Region (M6.11), Updates and System are in); About closes the list. A page may have no section of the file (Sound's volume and devices are the sound system's own, the one key of Sound is low latency (M7.6b), and so are Bluetooth's pairings and Network's connections and passwords, which never go in the file, ADR-006), and a page that only runs `edel` (Updates and System) needs no feature.
- Every change is one key of the person's settings file (`edel::places::person_settings`, no privilege needed), written with `edel::settings::set` and `unset`, the functions `edel settings set` and `reset` use, so a refused value reads the same in a row and on the command line, and the file is byte for byte what the command would write. A choice that is what would apply anyway is taken out of the file, never written (ADR-008: writers never write a default).
- Every page works at every size class (M5.6c): at Compact width, 360 logical px, nothing is cut off and nothing scrolls sideways, and in touch mode every control is at least 44 px (Alimardon, 2026-10-08: phones later, so nothing built now needs rework, M9). From M5.8b on, a page's CI case also draws it at Compact width.
- Nothing of its own runs in the background; the desktop follows the file it writes (the compositor watches it, M4.5).
- Every word people read, shown or spoken to a screen reader, is marked with `edel::i18n`'s `tr`, `trf` or `n_` (M5.24a), and `po/settings.pot` is written afresh with `EDEL_WRITE_DOCS=1 cargo test -p edel i18n` in the same commit; log lines stay English.
- **Stands alone (M8.13):** it needs the `edel` library without its `cli` feature but with `os` (the install plan, firmware, the feature file reader: Settings is the system's own app, M6.17), GTK 4 and libadwaita, and the settings file, which it writes through `edel::settings`. It depends on no other part of ours at build time, and the desktop follows it only through that file; at run time it runs only `edel-shell-ui`, for the Lock screen page's look pictures, empty frames where it is missing (`ci/seams.sh`'s `allowed_program()`).

## Checks

The root CLAUDE.md's Rust checks cover it (the runner needs `libgtk-4-dev libadwaita-1-dev`); `ci/build.sh` builds it in Alpine with `gtk4.0-dev libadwaita-dev`, and the `settings` feature ships it. desktop-test's `settings` case opens it, checks our title bar and its colours, clicks Mac-like's card, Classic's and Reset, folds it on a narrow screen and holds its own memory to `settings_own_mib` in `ci/budgets.toml` (`ci/CLAUDE.md`). To see it without an image, use `sh ci/look.sh NAME edel-settings --page PAGE` (Docker): it builds and runs Settings, the compositor and shell-ui inside the release's Alpine with the image's GTK, libadwaita, fonts, `gtk.css` and feature files, maximizes the window as the `settings-tour` case does and keeps `out/look/NAME.png`, which matches CI's picture of the page; send that picture in the thread while coding. Never show a picture drawn with the host's own GTK: Ubuntu's GTK 4.14 and libadwaita 1.5 lay rows out otherwise and miss the light block of `gtk.css`, and without the image's feature files Settings hides most pages, so such pictures looked narrow and wrong (2026-10-17). A page that reads a battery (Power) shows none in Docker; to draw it with one, copy `ci/look.sh` to a scratch file, bind a fake `/sys/class/power_supply` read-only into the container and put a fake `upower` script that prints a laptop's `upower -d` in `target/look/debug`, then delete the copy (M7.16e, 2026-10-17).

The look to match: build every page from `widgets.rs`'s blocks (page, section, rows, cards, `big_button`, `banner`) and `style.rs`, never GTK's stock dialogs or widgets styled by hand, and hold a new page beside the polished ones in CI's `settings-tour-*.png` (Appearance, Shortcuts, Power, About) before it merges.
