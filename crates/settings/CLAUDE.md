# Settings (`edel-settings`)

Settings, the app for every setting (ADR-008, roadmap M5.6): GTK4 and libadwaita, as ADR-004 chose for our apps, the one app of ours on them, drawn in our own look (ADR-004's own look decision of 2026-10-06): every colour, corner and font from the design tokens, our own icons, the compositor's title bar, never GNOME's look. Match `docs/mockups/` where they show a page; where they are silent, build from the blocks in `widgets.rs`. Edition 2024, `rust-version = "1.85"`, GPL-3.0-or-later, `publish = false`; not a default member, so `cargo run` builds only `edel`.

## What belongs here

- A page per section of the settings file, named and ordered by `edel::settings::PAGES`, the table `edel settings` prints, so the app and the command never disagree (ADR-008's same names decision). A page is added in the step that brings its section (M5.7 to M5.10, M5.12; Layout, Displays, Sound, Network, Bluetooth, Notifications, Updates and System are in); About closes the list. A page may have no section of the file (Sound's state is the sound system's own, and so are Bluetooth's pairings and Network's connections and passwords, which never go in the file, ADR-006), and a page that only runs `edel` (Updates and System) needs no feature.
- Every change is one key of the person's settings file (`edel::places::person_settings`, no privilege needed), written with `edel::settings::set` and `unset`, the functions `edel settings set` and `reset` use, so a refused value reads the same in a row and on the command line, and the file is byte for byte what the command would write. A choice that is what would apply anyway is taken out of the file, never written (ADR-008: writers never write a default).
- Every page works at every size class (M5.6c): at Compact width, 360 logical px, nothing is cut off and nothing scrolls sideways, and in touch mode every control is at least 44 px (Alimardon, 2026-10-08: phones later, so nothing built now needs rework, M9). From M5.8b on, a page's CI case also draws it at Compact width.
- Nothing of its own runs in the background; the desktop follows the file it writes (the compositor watches it, M4.5).
- Every word people read, shown or spoken to a screen reader, is marked with `edel::i18n`'s `tr`, `trf` or `n_` (M5.24a), and `po/settings.pot` is written afresh with `EDEL_WRITE_DOCS=1 cargo test -p edel i18n` in the same commit; log lines stay English.

## Layout

- Pages name the feature they talk to (`Page::needs`) and are hidden when the machine has no `features/NAME.toml` in `edel::features::DIR` (`pages_in`); tests hide one in a temp directory and fail when a page names a feature with no file under `features/`.
- `main.rs`: the application (`edel-settings --page NAME` opens a page at the start, by its section or title or the start of one of them, `displays` or `display`; a name no page has is refused with the pages there are, `start_page`; a page opened by name gives the keyboard to its main control, and GTK itself is given only the app's id; `APP_ID`, which `features/settings/usr/share/applications/APP_ID.desktop` is named after; a test holds them together) and the window: a plain `gtk::ApplicationWindow`, not libadwaita's, so the compositor draws its title bar with the person's buttons (GTK asks through KDE's server decoration protocol); an `AdwNavigationSplitView` in an `AdwBreakpointBin` with a 204 px sidebar (`SIDEBAR`), as the mockups draw it: a search field (`finds`: a page's title or its rows' titles; Ctrl+F; Return opens the first found) and the pages with our icons; below 600sp (`NARROW`) the split view collapses and a page shows a way back. Pages are built when first shown and kept.
- `style.rs`: `Theme`, the tokens in the scheme the desktop shows (the settings portal, through `adw::StyleManager`), and `css`, the one stylesheet written from them, again when the scheme changes, when `watch`ers redraw too; only spacing is written here, every colour, radius, the font and the text's size are the tokens' (`window`, `card`, `line`, `panel`, `title_text`, `title_text_unfocused`, `accent`, `shadow`, `title_close_hover` for problems, `radius_*`, `text`, `font.interface`). A test fails when a colour is written here.
- `icon.rs`: `Icon`, a GTK symbolic paintable of one of `design/icons/`, drawn by `edel::icons` (feature `icons`) and painted in the colour of the text around it, so selection and the scheme recolour it; `image(name, size)` centred at its size.
- `widgets.rs` also holds `ChangeBar` (M5.6a): changes apply at once, so the desktop is the preview; once the person's file differs from what it was when the page opened, a pill floats up with Undo (`Files::restore` puts the file back) and Keep; Save as preset joins it with M5.17, and pages whose changes can strand a person (Displays) will undo by themselves after 15 s unless kept.
- `widgets.rs`: the building blocks every page is made of (M5.8d added `Hero`, `big_button`, `banner` and `disclosure`, a fold-out that starts closed), and with `card.rs`, `icon.rs`, `preview.rs` and `style.rs` the only files that call GTK (ADR-004's own look decision; another toolkit would be these again, M10.8): `page` (title, what the page is for, a line for problems, scrolling, at most `PAGE_WIDTH`), `section` (a heading with where its value comes from, Reset and Copy as command), `heading`, `group` (a card of rows), `row` (title, a line under it, Reset, Copy as command, the control), `value_row`, `copied`, `action` (a button for something to do now) with `output_row` and `say` (what a command said, in a fixed-width font, red when it failed), `pick_file`, `Choice` (a value from a few, in a list) and `Segments` (a value from a few, all in view, one click).
- `preview.rs`: a preset's picture on its card, drawn with cairo from the preset's file (its bars and docks with their widgets as marks, its windows floating or tiled with the buttons on its side) in the tokens' colours, drawn again when they change.
- `files.rs`: `Files` (the machine's file and the person's), `layout()` (each Layout key's value: the person's over the machine's, then the preset, then the release: `Layout::value`), `choose` (a key written, or taken out when it is what would apply without it), `set`, `source`, `shortcut` (an action's keys as the desktop follows them, for a row's text), `title` (a preset's name as people read it). Tested on files in a temp directory: never a default written, the file equal to `edel settings set`'s, a refused value's text equal to the command's.
- `layout.rs`: the Layout page as `docs/mockups/classic-menus.jpg` draws it: a card per preset (`edel::presets::NAMES`, in the order people see them) with its picture and a check on the chosen one, then Tile windows (a switch) on a card of its own, as the mockup has it, and a Title bars group holding everything about title bars, each row named as its key is: a small window whose bar is drawn as the compositor draws it (`widgets::BarPreview`, following every choice at once), Title bars and Window buttons (lists of the key table's values), and Minimize button, Maximize button and Close button (switches, M5.18a); each row shows the shortcut that does the same as keycaps (`widgets::show_keys`, from `Files::shortcut`, so a rebinding shows); the presets' heading says where the preset comes from (`rows::describe`) and each row's line adds `From the preset`, `Your choice` or `Set by this machine` (`rows::note`), with Reset for the person's own value and Copy as command, which shows while the pointer is over its row; `Ui::update` shows the files' state after every change and whenever a file changes (a `gio::FileMonitor` on each), so the panel's toggle and `edel settings set` show here too.
- `rows.rs`: `ROWS`, every row with its key (a test holds each to a supported key of `edel::settings::KEYS`), `on_page` (a page's rows, for search), `values` (a key's values from the key table), `label` (`floating-only` reads Floating only), `describe` (`Your choice`, `Set by this machine`, `Automatic (VALUE)`, from `edel::settings::source`, for the presets' heading), `note` (a row's: nothing when the release decides, `From the preset` when the preset does), `command` (the `edel settings set KEY=VALUE ...` line for a row's keys) and `resettable`.
- `display.rs` (M5.7a): the Displays page: the arrangement picture (`preview::arrangement`, the screens side by side to scale, in the tokens' colours, one pane per screen, an outline for one that is off), then a heading and a card for each screen with Scale (`widgets::Segments`: 100, 125, 150, 175 and 200 percent in one row, plus the current value when it is none of them), Resolution (`widgets::Choice` of the sizes the screen lists), Position (two spin buttons, `[x, y]` in logical pixels) and On (a switch), each row named by `rows.rs`'s `displays.*.KEY` and writing one line `displays.NAME.KEY` of the person's file with Reset and Copy as command. Scale comes first: it is what most people come here for, and it keeps Reset on screen when the scale is 200 percent and the window is larger than the screen (desktop-test's `display` case clicks it). A screen's own default (`preferred_mode`, `auto_scale` from the state file) is never written (`Files::choose_over`), and the last screen that is on refuses to turn off, with a message that says what to do. The page follows the settings files and the state file (`gio::FileMonitor` on each) and builds its rows again only when `Shape`, the screens and their choices, changes, so a window moving never rebuilds it.
- `screens.rs` (M5.7a): `list`, the screens to show, from the state file's `[[outputs]]` (name, scale, `auto_scale`, `mode`, `modes`, `preferred_mode`, place) and the files' `[displays]` for what the state cannot say (a screen turned off is not in it, and without a session there is no state: then every screen the files name is listed), `scale_choices`, `mode_choices`, `arrange` (the picture's rectangles), `logical` (a mode at a scale) and `on_count`. No toolkit, all tested; nothing assumes how many screens there are or that they are local (ADR-011, M7.10d: a paired device's screen is one more entry).
- `sound.rs` (M5.7b): the Sound page: an Output and an Input card, each a list of the devices PipeWire reports (`edel::sound::read`, `wpctl status`, so not assumed local, ADR-011), a volume slider (steps of 5, at most `edel::sound::MOST_PERCENT`; one `wpctl set-volume` once it settles for 120 ms) and a mute switch, each row copying its `wpctl` command; the page follows the sound system every 2 s while mapped (a person's own change holds it off for 3 s) and has no Reset or key, as the volume and the chosen device are WirePlumber's own live state; reads and writes run on `gio::spawn_blocking`, and a failure reads in the page's problem line in `edel::sound`'s words. Its slider carries the keyboard when the page was asked for by name (`widgets::ASKED`, `take_asked`). It needs the `sound` feature.
- `card.rs` (M5.8a): the blocks of a page about the state of one thing: `Glance`, the card at the head (a large icon, one plain headline and a line under it, an `aside` for a switch; the icon in the accent when on, muted when not, a screen reader hears both as one sentence), `fold` (a closed fold-out for what only technical people read, "Details"), `bars` (a Wi-Fi network's signal as four bars, `edel-bar-part`, lit in the accent), `while_shown` (a timer that ticks when a page comes on screen and every few seconds while it stays, never hidden: a page of live state looks only while someone sees it) and `clear`. The look is `style.rs`'s (`edel-glance*`, `edel-bars`, `edel-lock`, `edel-entry`, `edel-fold`), written from the tokens.
- `network.rs` (M5.8a): the Network page, as plain as a phone's: a card with one headline (`headline`: Connected to NAME and how, Connected by cable, Connecting, Not connected with what to do, Networking is off), the wired connection (`wired_text`; hidden with no wired device), the Wi-Fi switch with Look again (hidden with no adapter) and the networks in range (`edel::network::read`, `nmcli -t`): name, how it stands (`note`: Connected, Saved, Needs a password, Open network), signal bars, a padlock whose place is kept so the columns line up, Connect (a password in a row under the network, Enter or Join; a remembered network joins with none), Disconnect and Forget (two clicks); a failed new network is not kept and a wrong password reads `the password for NAME was missing or wrong`. Addresses and the rest are under Details, read only while it is open. Reads and changes run on `gio::spawn_blocking`; the page looks every 4 s while mapped (not during a change, and the list is made again only when a row would change, never while a password is being typed); each row copies the `nmcli` command that does the same (a password is `PASSWORD`, never the real one); it says once on stderr `edel-settings: network page shows "HEADLINE"` for desktop-test. No key, no Reset: the connections and passwords are NetworkManager's. It needs the `network` feature.
- `bluetooth.rs` (M5.8a): the Bluetooth page: a card with the switch (Bluetooth is on and what it is connected to, Bluetooth is off, or `This computer has no Bluetooth` and nothing else on the page), Your devices (paired: Connect or Disconnect, Remove with two clicks; `note` says what kind of thing it is and whether it is connected), Nearby devices (Search runs `bluetoothctl --timeout 10 scan on` on a thread, the list follows every 2 s meanwhile; Pair pairs with the `NoInputNoOutput` agent, trusts and connects; a nameless device, which BlueZ names by its address, is hidden unless paired) and Details. As Network: threads, 4 s while mapped, copyable commands, one stderr line (`edel-settings: bluetooth page shows "HEADLINE"`), no key and no Reset (BlueZ's pairings and their keys are its own). A keyboard that asks for a code to type is a seam, noted on the page. It needs the `bluetooth` feature.
- `power.rs` (M5.8b): the Power page: a card with the battery in one plain headline (how full, charging or not, time left), or `Plugged in` on a machine without one, other devices' batteries (a wireless mouse) when UPower lists them, the `[power]` rows, and Details with UPower's own dump; read through `edel::power` on a thread of its own, every few seconds only while the page is on screen.
- `notifications.rs` (M5.9b): the Notifications page: one row, Do not disturb (`notifications.do_not_disturb`, a switch, `rows.rs`'s title), written with `Files::choose_over` (off is what applies without the key, so the key is taken out, never written `false` unless the machine's file says `true`), with Reset and Copy as command (`edel settings set notifications.do_not_disturb=true`) and the line `Banners stay away; notifications still collect in the list the clock opens` with where the value comes from; it follows the files while open (`gio::FileMonitor`), so quick settings' tile, the notification centre's switch and `edel settings set` show here too. It needs the `shell` feature, as shell-ui is what shows banners; nothing of its own runs. `Files::do_not_disturb` reads the key as shell-ui does (`edel::settings::flag`). Tested: the file equal to `edel settings set`'s, a refusal reading as the command says it.
- `users.rs` (M5.8b): the Users page: the person at the machine on a card, their name large, Administrator (`users.NAME.admin`) as a row, the other people, Add and Remove a person, and Details with login names, ids, homes and shells; read from `/etc/passwd` and `/etc/group` through `edel::users`, never a password. Changing people needs root, so until doas (M6.5) the controls are shown unusable with a line saying why and which `edel settings` keys an administrator can set now.
- `cmd.rs` (M5.8c): `edel(args)` runs the `edel` tool and gives an `Outcome` (exit status, output, message; `shown()` is what a person reads: the output on success, else the message as `edel` wrote it), and `line(args)` the command for Copy as command. Called from `gio::spawn_blocking`, never from the thread that draws. Changing the machine needs root until `doas` (M6.5), which will be run here; until then a refusal is shown as it is.
- `updates.rs` (M5.8c, remade in M5.8d at Alimardon's ask of 2026-10-08: "check for updates, update and rollback big buttons at the top ... a smaller update settings section below", for people who are not technical): what an updates page is everywhere, in that order. A card at the top (`widgets::Hero`: a big icon of ours, `status-ok`, `status-new`, `status-restart`, `status-problem` or `status-sync`, or a spinner while a command runs, a headline and a line under it) and the big buttons under it (`widgets::big_button`, tall, the leading one filled with the accent, Go back outlined, wrapping when the window is narrow): Check for updates, then Update now, then Restart now, and Go back to VERSION, asked twice (5 s), shown only when `edel status` has a confirmed older version in the other slot and nothing waits for a restart. A button's tooltip says the command it runs. What's new, only after a check found a newer version: its version, date and size (a seam: release notes join it when `release.toml` has a `notes` field). Update settings: the Channel row (`updates.channel`: `edel::settings::CHANNELS` and the one followed, a plain line under it, Stable's or Preview's, then Your choice or Set by this machine; Reset, Copy as command, written with `Files::choose_over` so the image's own channel is never written) and Install updates automatically, an off switch that says it is not available yet (`updates.automatic` and `updates.restart_window` are keys nothing follows until M7.5; no row of `rows.rs` claims them until then). Details, closed: the slots (`facts`: Running now, Starts next, each slot's version and whether it was confirmed, `effects`, `logs`, the command's own message when `edel status` fails, which it does for a person until doas) and the last command as typed with its raw output. Nothing runs on a timer: `edel status` is read when the page is shown and after each action, and prints `edel-settings: updates page read edel status, exit N` on stderr for desktop-test; the commands (`cmd::edel`, `cmd::reboot`) run on `gio::spawn_blocking`. Restart now runs `reboot`, there being no `edel` command for it. It follows the settings files.
- `status.rs` (M5.8d): the Updates page without a toolkit, all tested: `Status::parse` (`edel status`' slots; `pending`, a version waiting for a restart or a rollback doing so; `rollback_to`), `parse_check` (`edel update --check`'s `available:`, `newer:`, `released:` and `size:` lines), `Phase` (idle, checking, up to date at a time, available, installing, installed, going back, restarting, failed) and `view`, the one `View` each state draws: icon, headline, line, leading button, Go back's version, the What's new card. The words are the familiar ones ("Edel OS is up to date", "An update is available", "Restart to finish updating", "Couldn't check for updates"); a failure says why in plain words (`plain_failure`: no network, or administrator rights Settings cannot ask for until doas, M6.5) and never claims "up to date" before a check ran.
- `system.rs` (M5.8c): the System page: Save as writes `edel settings export` into a file chosen with GTK's file dialog (`widgets::pick_file`); Choose file runs `edel settings diff FILE` and shows the changes (`diff`, from the command's `change:` lines, since its exit status 1 means changes as well as failure), and only then Apply runs `edel settings import FILE`; Copy as command gives each command. Developer mode and profiles join with M7.1 and M7.6.
- `about.rs` (M5.6a, made friendly in M5.8d): the About page as an "About this computer" is everywhere: the system's name large (`NAME` of `/usr/lib/os-release`) and `Version VERSION_ID · Channel` under it in a card (`widgets::banner`) with two big buttons, Check for updates (it activates the window's `win.show-page` action, which `main.rs` adds: the sidebar follows and a narrow window shows the page) and Copy system info (`info_text`, the rows as plain text); rows for this computer, each read from `/proc` and `/sys` without a crate and left out when the machine does not say (`computer_rows`, testable on a folder standing for `/`): Name (the host name), Device (`device_name`: the firmware's vendor and product, not its placeholders), Processor (`cpu_text`: the model without trademark signs, `× threads`), Memory (`memory_text`: the usual size just above what `MemTotal` shows, `16 GB`), Graphics (`graphics_name`: the first card's maker by PCI vendor, else its driver) and Storage (the volume under the home folder, from gio: `74 GB free of 128 GB`); then the last `edel::session_log::LAST_LINES` lines of the person's session log (`edel::places::person_state_dir`) in an expander (`widgets::log_row`), or `widgets::text_row` saying plainly where the log will be written when there is none yet (M5.28b).

## Checks

The root CLAUDE.md's Rust checks cover it (the runner needs `libgtk-4-dev libadwaita-1-dev`); `ci/build.sh` builds it in Alpine with `gtk4.0-dev libadwaita-dev`, and the `settings` feature ships it. desktop-test's `settings` case opens it, checks our title bar and its colours, clicks Mac-like's card, Classic's and Reset, folds it on a narrow screen and holds its own memory to `settings_own_mib` in `ci/budgets.toml` (`ci/CLAUDE.md`). To see it without an image: run `edel-compositor` nested (it uses winit when `WAYLAND_DISPLAY` or `DISPLAY` is set, as under `Xvfb`) and start `edel-settings` on its socket; GTK 4.14 on Ubuntu warns about the light block of `gtk.css`, which 4.22 in the image reads; `ADW_DEBUG_COLOR_SCHEME=prefer-dark` shows the dark scheme, and `GSK_RENDERER=cairo` draws without a GPU.
