# CI scripts

`.github/workflows/ci.yml` (workflow "CI") runs on every pull request and every push to `main`; a new push to a pull request cancels that pull request's older run. Its two jobs run in parallel on `ubuntu-latest`: "Rust checks" (the cargo commands in the root CLAUDE.md) and "Build and boot images" (the scripts here). There is no toolchain pin; the images job caches `.cargo-home` and `target`, keyed on `Cargo.lock`.

| Script | What it does | Needs |
|---|---|---|
| `build.sh` | Installs the build tools (`apk add --no-cache cargo dosfstools e2fsprogs e2fsprogs-extra grub grub-efi mtools openssh-keygen sfdisk tar`; add any new build-time tool to this line in the same PR), runs `cargo build --release --locked`, builds every image through its `build VERSION ARGS` helper (`--version`, from `EDEL_VERSION` or `0.1`; `--channel` from `EDEL_CHANNEL` or `ci`; one shared `--apk-cache out/apk-cache`), builds every `images/*.toml` into `out/`, makes two throwaway signing keys in `out/keys/`, builds the install test image into `out/install-test/` (the VM image with `ci/ab-test/files` and `ci/install-test/files`, `--health-timeout 30` and both public keys), builds the system test image into `out/system-test/` (the VM image with a seed `/usr/share/edel/system.toml` naming the machine `ci-seeded`, adding admin user `ci` and giving `ci` and root a fresh ssh key, `out/keys/ci-ssh`, plus an unknown key and a comment), builds the A/B update (`--files ci/ab-test/files`, `--health-timeout 30`, both public keys, `--loader-tag ci`) into `out/ab-test-update/` and its update directory `out/ab-test/update/` (a signed `release.toml`, the gzipped image, and `bad.toml` with one byte changed), builds `ci/flatpak/vm.toml` into `out/flatpak/`, then hands the finished files back to the checkout's owner | Root in the privileged `alpine:3.24` container (the `docker run` line in the root CLAUDE.md), the Alpine mirrors and crates.io |
| `container-test.sh` | Imports `out/edel-container-x86_64.tar.gz` as `edel:ci` and checks for lines starting `Edel OS ` and `apk-tools ` | A Docker daemon, a real build |
| `boot-test.sh` | Boots `out/edel-vm-x86_64.img` through OVMF and GRUB; passes on `edel login:`, `Welcome to Edel OS`, `edel update: slot A confirmed`, `edel-data: mounted /data` and `Edel OS <EDEL_VERSION>, channel` (printed by `edel-boot-ok`); then boots a copy 3 GiB larger and checks that `df -m /data` shows more than 2048 MiB (ext4 keeps about 7 percent for itself); logs in `out/boot.log` and `out/boot-grown.log` | QEMU and OVMF; KVM if present |
| `system-test.sh` | Boots `out/system-test/` with port 2222 forwarded to the VM's ssh, waits for `ci-seeded login:`, then logs in as `ci` with `out/keys/ci-ssh` (ten tries, 3 s apart) and runs `edel system export`, which must have `hostname = "ci-seeded"`, `[users.ci]` and `admin = true`; then as root: diff is empty after apply, `set network.hostname=other` changes only that line and diff shows exactly that change, and after `unset` and apply `hostname` prints `edel`, with the seed's `future.key = 1` and the comment above `[users.ci]` kept; logs in `out/system-test.log`, `out/system-export.toml`, `out/system-diff.log` and `out/ssh.log` | QEMU and OVMF, KVM if present, an ssh client |
| `install-test.sh` | Boots `out/install-test/` with a blank 3 GiB second disk, `out/install-target.img`; its background test service waits for slot A to be confirmed, runs `edel install /dev/vdb --system /usr/share/edel/ci/install.toml` without `--yes` (the plan, exit 3, the disk's sha256 unchanged) and then with it; saves the live image's ssh host key in `out/install-live-key` (the service prints `INSTALL-TEST: host key` on every boot); log in `out/install-test.log` | QEMU and OVMF; KVM if present |
| `ab-test.sh` | Serves `out/ab-test/update/` over HTTP on port 8000 (the VM reaches it as `10.0.2.2`), boots the disk `install-test.sh` installed, `out/install-target.img` (M2.5), and waits for `AB-TEST: PASS` or `AB-TEST: FAIL`; its first boot must also show `edel system: network.hostname: set to ci-installed`, `slot A confirmed` and an ssh host key other than the live image's; logs in `out/ab-test.log` and `out/http.log` | QEMU and OVMF; KVM if present |
| `flatpak-test.sh` | Boots a copy of `out/flatpak/edel-flatpak-x86_64.img` made 6 GiB larger, with 2 GiB of memory; its test service runs `/usr/share/edel/ci/flatpak-steps.sh` as user `ci`: adds Flathub, installs the newest `org.freedesktop.Platform` (900 s at most) and then the oldest (600 s at most), runs a shell from each and prints `FLATPAK-TEST:` lines, with the tail of any install error; passes on `FLATPAK-TEST: PASS` (the newest runtime ran); log in `out/flatpak-test.log` | QEMU and OVMF, KVM if present, and Flathub |
| `vm.sh` | Sourced, not run: picks KVM when `/dev/kvm` is writable, else TCG; finds OVMF; adds an `i6300esb` watchdog with `-action watchdog=reset`; defines `run_vm LOG PATTERN TIMEOUT [QEMU ARGS]`, which sets `found` and `waited`; `vm_net` adds user network options (`hostfwd`), and with `keep_vm=1` the VM keeps running after the pattern until `stop_vm` | |
| `keys-check.sh` | Fails when a line of `crates/edel/tests/keys.txt` was deleted, compared with `main`, without a bump of `FORMAT` in `system.rs` ("Rust checks" runs it) | git and `origin` |
| `packages.sh` | Prints the `### Packages` section of the run summary: each `out/*.packages` against the preview release's copy, or its package count while no preview exists; a record, never a gate; always exits 0 | `curl`, GitHub Releases |
| `sizes.sh` | Prints the `### Image sizes` table for the run summary (CI runs it even after a failure); always exits 0 | `sudo` to measure the root-owned `out/work/` |

## Rules

- Run every script as `sh ci/NAME.sh` from the repository root, as CI does; `ab-test.sh` and `vm.sh` are not executable, and all of them use relative paths.
- CI numbers each build `YYYY.MM.N` with N the run number (step "Number this build") and passes it into the build container as `EDEL_VERSION`; the A/B update is that version plus `.1`, so it is newer.
- On the runner, CI installs QEMU and OVMF with `sudo apt-get update && sudo apt-get install -y qemu-system-x86 ovmf`, after an "Enable KVM" step that opens `/dev/kvm` with a udev rule.
- Write POSIX sh that both busybox (`build.sh` runs in Alpine) and dash (the tests run on the Ubuntu runner) accept: `#!/bin/sh`, `set -eu`, tabs, quoted expansions, no bashisms, a header comment saying what the script does and why.
- Never run `build.sh` outside the `alpine:3.24` container: it needs apk, root and the host keys in `/etc/apk/keys`.
- VM tests open disks with `-snapshot`, so the images stay as built. `ab-test.sh` leaves out `-no-reboot` because the VM restarts between steps.
- The A/B steps run inside the VM from the OpenRC service `ab-test/files/etc/init.d/edel-ab-test` (a committed runlevel link enables it; it needs `edel-boot-ok`). It keeps its step number in `ab-test-step` on the EFI system partition and downloads every update from `http://10.0.2.2:8000/`. On a boot with a second disk (the install test's live boot) the service does nothing. Step 1 checks the read-only root, expects `refused: signature` for `bad.toml`, writes markers into `/home` and `/var`, deletes `/var/lib/ci-new`, changes the hostname with `edel system set` and `apply`, notes the ssh host key, adds a user, drops a system user from the machine's `/etc/passwd` and installs into slot B; step 2 expects all of that kept, the shrunk update grown to the full slot (`df -m /` above 900), its tagged boot loader on the ESP with `BOOTX64.EFI.prev` kept, the dropped system user and `/var/lib/ci-new` back from the slot, and rolls back to slot A by command; step 3 expects the markers and slot A's loader back on the ESP, installs into slot B again and breaks its initramfs; step 4 expects `B: ok=0 try=3`, the markers and `from = "B"` in `/data/edel/last-fallback.toml`, checks that a rollback to slot B is refused and installs slot B again with a service that hangs; step 5 expects slot B off after three watchdog restarts and installs it again with a service that freezes the kernel with panic reboots off; step 6 expects slot B off again and prints `AB-TEST: PASS`. The install test image and the A/B update are built with `--health-timeout 30`. A mismatch prints `AB-TEST: FAIL: step N expected "LINE"` and powers off.
- VM tests leave the built images unchanged: they open them with `-snapshot`, or boot a copy they delete afterwards (`flatpak-test.sh`). `ab-test.sh` leaves out `-no-reboot` because the VM restarts between steps.
- The A/B steps run inside the VM from the OpenRC service `ab-test/files/etc/init.d/edel-ab-test` (a committed runlevel link enables it; it needs `edel-boot-ok`). It keeps its step number in `ab-test-step` on the EFI system partition and downloads every update from `http://10.0.2.2:8000/`. Step 1 checks the read-only root, expects `refused: signature` for `bad.toml`, writes markers into `/home` and `/var`, deletes `/var/lib/ci-new`, changes the hostname, notes the ssh host key, adds a user, drops a system user from the machine's `/etc/passwd` and installs into slot B; step 2 expects all of that kept, the shrunk update grown to the full slot (`df -m /` above 900), its tagged boot loader on the ESP with `BOOTX64.EFI.prev` kept, the dropped system user and `/var/lib/ci-new` back from the slot, and rolls back to slot A by command; step 3 expects the markers and slot A's loader back on the ESP, installs into slot B again and breaks its initramfs; step 4 expects `B: ok=0 try=3`, the markers and `from = "B"` in `/data/edel/last-fallback.toml`, checks that a rollback to slot B is refused and installs slot B again with a service that hangs; step 5 expects slot B off after three watchdog restarts and installs it again with a service that freezes the kernel with panic reboots off; step 6 expects slot B off again and prints `AB-TEST: PASS`. The A/B image is built with `--health-timeout 30`. A mismatch prints `AB-TEST: FAIL: step N expected "LINE"` and powers off.
- A new VM case follows the same pattern: a test-only service inside the image and a serial line the host script waits for.
- Test-only files live under `ci/`, never in `images/`. They reach an image through `edel image build --files DIR`, or, when a test needs other packages or definition keys, through a CI-only definition or feature file under `ci/` (`ci/flatpak/vm.toml` in M1.9, `ci/features/ci-hello.toml` in M7.2a; M1.5's ab-test image sets `health_timeout = 30`). Release definitions never point into `ci/`.
- The tests grep exact strings: serial markers, `edel update status` lines, `/etc/issue`, `PRETTY_NAME`, the `edel` hostname. Change a string and its grep in the same PR.
- Timeouts: `BOOT_TIMEOUT` (300 s), `AB_TEST_TIMEOUT` (1500 s), `INSTALL_TEST_TIMEOUT` (600 s) and `FLATPAK_TEST_TIMEOUT` (1800 s). With KVM the VM reaches the login prompt in about 8 s and the A/B test takes about 75 s. No timing is recorded without KVM.
- CI keeps only `out/*.tar.gz`, `out/*.log` and `out/*.packages` (artifact `edel-images`); the VM disks are not uploaded, so a VM test cannot be rerun from CI outputs. On a failure, read the job log: the tests print the serial log.
- "Build and boot images" is the job that must pass before a merge: once Alimardon turns on branch protection for `main` (M2.5), GitHub refuses to merge while it is red.
- After a real build, `out/work/` and the `work/` directories under `out/install-test/`, `out/system-test/`, `out/ab-test-update/` and `out/flatpak/` stay owned by root; a local container run also leaves `target/` owned by root. Deleting them needs root.
