# Other projects' bugs, checked against ours (M8.11)

Roadmap step M8.11 reads the bug trackers of the projects nearest each part, sorts what they show into kinds of mistake, and checks each kind against our code and tests. Each kind we are open to gets a test and a fix. This file records the sources read, the kinds and what each led to; every kind names its test, or why it does not apply to us, or the step that will close it.

## Sources

Each tracker was read on 2026-10-24 as its 25 issues with the most comments (open and closed), or, where the tracker sorts so, the most votes or the most popular, the issues people meet most. GitLab and Bugzilla pages refuse a plain fetch, so those trackers were read through their REST APIs (GitLab's `/api/v4/projects/.../issues`, Bugzilla's `/rest/bug`).

| Part | Read |
|---|---|
| Compositor | niri, cosmic-comp, Sway, Hyprland, smithay, wlroots (freedesktop.org's GitLab) |
| shell-ui | Waybar, Cinnamon, the COSMIC panel, GNOME Shell (GNOME's GitLab), the Plasma panel (KDE's Bugzilla, `plasmashell`) |
| Settings | COSMIC Settings, GNOME Settings (GNOME's GitLab), Plasma's System Settings (KDE's Bugzilla, `systemsettings`) |
| Base, installer, updates | RAUC, bootc, Fedora Atomic (its issue tracker), AerynOS (os-tools), Alpine's aports and postmarketOS's pmaports (their GitLabs) |
| Tools | Flatpak, apk-tools (Alpine's GitLab) |

Calamares was not read: its tracker is archived and its issues moved, and we write our own installer (M7.4).

## Kinds of mistake

| The clock and time zones | Waybar #3575 (the bar shows UTC while everything else is local) | Every clock in shell-ui read jiff's system zone, which jiff keeps for five minutes, so after a person picked another zone in Settings, the panel, the lock screen and the greeter showed the old one for up to five minutes, and the automatic dark mode's words did too | Fixed: `edel::timezones::now` and `system` read `/etc/localtime` again as soon as the link changes, and every clock uses them; test `timezones::tests::the_zone_follows_its_link_at_once` |
| A full disk | from memory: settings and state files cut short when the disk fills | `edel::settings::write_text` writes a new file and renames it over the old one, so the old file survives, but a write cut short by a full disk left the half-written `settings.toml.edel-new` behind, filling the disk more | Fixed: the half file is taken out when the write or the rename fails; test `settings::tests::a_failed_write_keeps_the_file_and_leaves_no_half_file`. ## Principles check

- **Reliable:** each kind is a way a person was left with a broken session elsewhere; the fixes here: a clock in the wrong zone, a half file filling a disk, and a file the compositor or shell-ui would keep open for every window, now caught by `descriptors`.
- **Simple and modular:** each fix is in the one place that owns it (`edel::timezones`, `edel::settings::write_text`), and every clock reads the same function.
- **Traded off:** kinds that need real hardware (docks, the light, real screens) are left to the laptop walk (M8.15b) rather than imitated in the VM, and two open kinds (fixed account ids, Bluetooth codes) are written down for steps of their own instead of changing the base and a Settings page inside a review; the desktop tests grew by one case, `descriptors`, and one boot, `another-base`.
